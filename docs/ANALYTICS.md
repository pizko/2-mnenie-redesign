# Аналитика

## Что было на боевом сайте (по собранному JS)
- Яндекс Метрика **111152079**. Счётчик грузится **только после «Согласен»** в баннере cookie: ключ `localStorage['cookie-consent']` = `accepted | necessary`. При отказе удаляются куки `_ym*`.
- Одна цель: `site_to_bot` с параметром `{source}`. Значения `source` на боевом сайте: `hero`, `pricing`, `specialist`, `mobile_fab`.
- Атрибуция переходов в бот: `POST /api/public/attribution/clicks` с `{source, landing_path, ym_client_id, referrer}` → ответ `{start_param}` → `https://t.me/randomtox_bot?start=<start_param>`. `ym_client_id` передаётся только при согласии. Если ответа нет за 1,5 с, посетитель уходит в бота без параметра.

## Что в редизайне
Сохранено один в один: ключ согласия, условная загрузка Метрики, цель `site_to_bot`, контракт атрибуции и таймаут.
Источники `hero / pricing / specialist / mobile_fab` не переименованы — отчёты не ломаются.

Новые цели (параметры — только место на странице и публичный slug):

| Цель | Когда | Параметры |
|---|---|---|
| `cta_click` | нажатие ссылки «Оформить в Telegram» (теперь вторичный путь) | `place`: hero, header, mobile_menu, pricing, final, mobile_fab, specialist, catalog, reviews, not_found, article_<slug> |
| `site_to_bot` | то же нажатие (как раньше) | `source` = place |
| `sample_open` | открытие примера заключения (якорь или PDF) | `place`: hero, sample_section |
| `specialist_open` | переход к карточке врача | `place`: home, catalog; `slug` |
| `faq_open` | раскрытие вопроса FAQ | `place`, `n` (номер вопроса) |
| `lead_form_open` | открыта форма заявки (главная кнопка «Получить второе мнение — 3 500 ₽») | `place`: hero, header, pricing, final, mobile_fab, mobile_menu, specialist, catalog, reviews, not_found, article_<slug> |
| `lead_form_submit` | приёмник ответил «ок» на заявку. **Это не оплата.** | `place` |

Содержимое формы заявки (имя, почта, телефон, описание, файлы) в Метрику не передаётся. Никаких жалоб, текстов форм, имён, контактов и файлов в Метрику не уходит. Отзыв о враче отправляется только в API и в Метрику не передаётся.

## Чего на сайте измерить нельзя
- **Переход в Telegram ≠ заявка ≠ оплата.** `site_to_bot` — это только клик.
- **Начало оформления** (команда `/start` с параметром) и **оплата** происходят в боте и бэкенде. Код бота и бэкенда в этот репозиторий не входит.

## Рекомендация для бэкенда (не реализовано, нужен доступ к коду бота)
1. Бот при `/start <start_param>` фиксирует событие «начал оформление» по записи атрибуции.
2. Вебхук ЮKassa `payment.succeeded` по заявке находит `start_param` → `ym_client_id` (есть, только если посетитель дал согласие) и выгружает **офлайн-конверсию** в Метрику (Management API, `offline_conversions/upload`, цель вида `paid_consultation`) с суммой.
3. В конверсию передаются только `ClientId`, цель, время и сумма. Никаких данных питомца, жалоб и контактов.
