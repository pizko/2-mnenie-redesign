# Редизайн 2-mnenie.ru — отчёт

Дата: 24.10.2026. Снимок данных боевого сайта: `data/snapshot.json`.

## 0. Исходные условия (важно)
- **Исходного кода сайта у нас нет.** 2-mnenie.ru работает на стороннем сервере (217.114.2.13, Caddy, Next.js). В GitHub pizko и на VPS его нет, AGENTS.md недоступен.
- Поэтому редизайн — **новый фронтенд публичной части на том же стеке (Next.js App Router)**. Он подключён к тем же публичным API и повторяет найденные в JS-бандле интеграции:
  - данные: `GET /api/specialists`, `/api/reviews`, `/api/articles`, `/api/dosages`, `/api/specialists/{slug}/reviews`;
  - форма отзыва: `POST /api/specialists/{slug}/reviews` `{author_name, rating, text}`;
  - бот: `POST /api/public/attribution/clicks` → `t.me/randomtox_bot?start=…`;
  - Метрика 111152079 по согласию, тот же ключ `cookie-consent`.
- Кабинет, логин, регистрация врачей, бот, оплата и админка остаются в основном приложении — ссылки ведут туда.
- Production не трогали, реальных заявок, платежей и отзывов не отправляли. В проверках запросы к API атрибуции, Метрике и t.me подменялись.

## 1. Концепция «Ясность в сложной ситуации»
Разрозненные материалы — выписка, анализ, снимок — складываются в одно структурированное заключение. Это видно уже в первом экране (иллюстрация из трёх шагов с подписью «демонстрационные документы») и повторяется в sticky-сценарии «Путь ваших материалов».

- **Палитра:** тёплый молочный фон `#f7f2ea`, глубокий тёмно-бирюзовый `#123b3e` для текста и ключевых элементов, шалфейный (`#8fa88f` — декор, `#587259` — текст), светло-голубой `#d9e9ef`, мягкий янтарный `#e2a24a` / `#fbecd2` для пояснений. Все 24 текстовые пары проходят WCAG AA (`scripts/check-contrast.mjs`, минимум 4,75:1).
- **Типографика:** Source Serif 4 для заголовков (редакционный характер) и Golos Text для текста (шрифт с русской проектировкой). Два семейства, вариативный вес 400–700, по одному файлу ~35 КБ (кириллица и латиница вместе).
- **Ритм:** секции разные по устройству. Редакционный split с липким заголовком, нумерованные списки на линейках, «лист» заключения, тёмная полоса цены, лента врачей, большая цитата «О проекте». Одинаковой сетки скруглённых карточек нет, лапок, стекла и неона тоже нет.

## 2. Структура главной и почему так
1. **Первый экран.** H1 «Второе мнение ветеринара по диагнозу и лечению вашего питомца». Рядом цена, срок с точкой отсчёта, формат результата, CTA, ссылка на пример и пояснение «анкета, файлы и оплата — в Telegram-боте».
2. **Когда полезно** — 5 поводов (с оговоркой, что это не показания) и сразу блок «когда нужна клиника прямо сейчас». Встревоженному владельцу граница услуги важнее всего, поэтому она стоит наверху.
3. **Что вы получите + пример заключения (В и Е объединены).** HTML-разбор настоящего демо-PDF по разделам «рассмотрено → выводы → ограничения данных → вопросы лечащему врачу» и ссылка на PDF. Два отдельных блока повторяли бы друг друга.
4. **Как проходит обращение** — 5 шагов. На десктопе это sticky-сценарий, на мобильном — обычный список.
5. **Стоимость** — что входит, что не входит (со ссылками на пункты оферты), что проверить перед оплатой.
6. **Врачи** — реальные фото, специализации без «Другое», стаж только там, где он указан.
7. **После заключения** — только то, что следует из оферты, без новой услуги.
8. **Отзывы** — единственный реальный отзыв целиком, вместе с минусом. Честная подпись: «пока отзыв 1».
9. **FAQ** — 10 вопросов: сроки, материалы, дозагрузка, оплата, выбор врача, язык, вопросы после заключения, контакты, экстренные случаи.
10. **О проекте**, финальный CTA, единый футер.

Стоимость стоит перед врачами: цену ищут раньше, а доверие к врачам подкреплено уже в первом экране и примере заключения.

## 3. Внутренние страницы
- `/specialists` — сетка карточек, облако специализаций, CTA.
- `/specialists/[slug]` — фото (единственный приоритетный ресурс), компетенции, стаж с объяснением расчёта, цитата, образование / опыт / курсы таймлайном, галерея документов (`<dialog>`, стрелки, Esc, возврат фокуса), отзывы и форма отзыва (контракт API сохранён), JSON-LD `Person`.
- `/articles` — главная статья и список. `/articles/[slug]` — даты публикации и обновления, «Коротко», оглавление, комментарий врача с фото, контекстный блок услуги, FAQ, источники, «Читайте также», `Article` + `FAQPage`.
- `/dosages` — профессиональный раздел: бейдж «для ветеринарных врачей», предупреждение владельцам, поля «Источник / Проверил / Редакция», поиск, фильтр по видам (`?q=`, `?species=`), алфавит. **Дозировки не менялись.**
- `/reviews`, `/documents/{offer,privacy,disclaimer}` (текст 1:1 с боевого сайта), 404.

## 4. Анимация
- Hero: короткое появление (≤0,8 с, ступенчато); у H1 и лида — только `transform`, без прозрачности, чтобы не задерживать LCP. Документы «прилетают», затем появляются чип «врач изучает» и лист заключения (до ~3 с). Потом остаётся только пульс точки, и он ставится на паузу вне экрана.
- Sticky-сценарий: состояние визуала меняется по IntersectionObserver, прокрутка не перехватывается. Ниже 1024 px сценарий не включается.
- Появление секций при прокрутке: один observer на страницу. Без JS контент виден сразу, есть страховочный fallback через 2,5 с.
- Кнопки и карточки: `transform` и тень. FAQ: нативный `<details>` с плавным раскрытием там, где браузер поддерживает `::details-content`. Галерея: мягкое появление.
- `prefers-reduced-motion` выключает всё, кроме смены состояний. Анимируются только `transform` и `opacity`. Новых библиотек нет.

## 5. Технические и SEO-исправления
| Проблема аудита | Что сделано |
|---|---|
| description карточки врача ≈ 2 879 символов (биография) | Отдельные короткие описания 120–150 символов (`content/doctors.ts`); для новых врачей — автообрезка по слову. |
| OG/twitter разделов наследуют главную | `pageMeta()` на каждой странице: свои title, description, canonical, og:url и **своё OG-изображение** (5 разделов + 7 врачей, 1200×630). Проверка: 22/22 URL уникальны. |
| lastmod в sitemap = время запроса | Статьи — `updated_at`, оферта и политика — дата редакции (14.08.2026). Где реальной даты нет (главная, разделы, врачи), lastmod не выводится. |
| Фото врачей в `/api/`, закрытом robots | Фото и сертификаты отдаются из `/media/specialists/<slug>/…` (webp, 4 ширины). `/api/` в robots остаётся закрытым целиком. |
| Портреты ниже первого экрана с preload | Приоритет (`fetchpriority=high`) только у фото на странице врача. На главной ни одного preload картинки. Логотип (43 КБ jpg → 1,2 КБ webp) больше не тянет лишнего. |
| Адаптивные изображения | `srcset` + `sizes`, `width`/`height` у всех `<img>`, `aspect-ratio`. CLS = 0 на всех замеренных страницах. |
| HTML справочника 705 КБ | 379 КБ без сжатия / 80 КБ gzip (было ~100 КБ gzip). Весь контент по-прежнему индексируется. Фильтр работает по уже отрисованному DOM, данные в JS не дублируются. `content-visibility:auto` для статей справочника. Дальше уменьшить можно разбивкой на страницы по буквам (`/dosages/a` …) — это новые URL, только с вашего согласия. |
| Кеширование | Публичные страницы: `public, max-age=0, s-maxage=300, stale-while-revalidate=86400`. `/media` — 7 дней, шрифты — год. Пути кабинета, логина и `/api` исключены и остаются за основным приложением (`private, no-store`). |
| canonical на главную в 404 | Убран. У 404 `noindex`, ссылки на основные разделы. |
| Разные футеры | Один `Footer` на всех страницах: разделы, документы, «Настройки cookie», реквизиты, предупреждение. |
| alt не по смыслу | Фото: «ФИО, ветеринарный врач». Сертификаты с подписями-файлами («IMG_5914», «1000156338») → «Сертификат N из M — ФИО». Декоративный логотип — `alt=""` рядом с текстовым названием. |
| Структурированные данные | Сохранены `VeterinaryCare` и `FAQPage`. Добавлены `BreadcrumbList` (все внутренние), `Person` (врачи), `Article` (статьи). `AggregateRating` не ставим: 1 отзыв, отзывы о себе. Расширенные сниппеты не обещаем. |

**URL:** все прежние адреса сохранены, редиректы не нужны. Слеш на конце → 308 на адрес без слеша (как сейчас, поведение Next.js). Параметры `?q=`/`?species=` у справочника не меняют canonical.
**HTTP/HTTPS, www:** http → https работает (Caddy). **https://www.2-mnenie.ru не отвечает** — это ошибка, исправление см. OWNER-DECISIONS №18.

## 6. Результаты проверок
Условия: Linux VPS, `next start` (production-сборка), Chromium 145 (Playwright), лабораторные замеры. **Это не полевые CWV**: полевые данные будут видны в CrUX и Метрике после выкладки.

**Автопроверки (все проходят):**
- `next build` и `tsc --noEmit` без ошибок.
- `scripts/check-site.mjs`: 22 URL из sitemap отдают 200; title и description уникальны и ≤ 200 символов; canonical и og:url совпадают; один H1; у всех img есть alt и размеры; картинок из `/api/` нет; 30 внутренних ссылок живые; 404 без canonical и с noindex.
- `scripts/check-interactive.mjs` — 20 проверок: меню (aria-expanded, фокус, Esc), skip-link, FAQ с клавиатуры, sticky-сценарий, галерея (стрелки, Esc, фокус), баннер cookie, Метрика только после согласия, переход в бота с `start=` и правильным телом атрибуции, уход в бота через ~1,6 с при недоступном API, фильтр справочника.
- `scripts/check-contrast.mjs` — 24/24 пары ≥ 4,5:1.
- Горизонтального скролла нет на 360 / 390 / 768 / 1024 / 1440 px для 9 типов страниц.

**Lighthouse 12** (мобильный профиль, simulated throttling, локальный сервер):
